## 1. 项目现状(截至 v0.3.2,2026-08-28)

> v0.3.x 代码已提交 GitHub:`2818c8f`(v0.3.0 合并提交:对话体呈现 + SVG 人物头像 + LLM 提示词优化)。

### 1.1 产品定位

「歧路」是一款 AI 互动叙事游戏(MVP 阶段):玩家在多分支悬疑剧本中做选择,由 LLM(DeepSeek)实时生成叙事与反馈,最终走向不同结局。

- 剧本1:《午夜列车》(悬疑/无限流,6 章,5 结局)
- 剧本2:《规则楼》(无限流/规则怪谈,3+ 结局)
- 模式:Mock(脚本驱动,可离线测试)/ LLM(生产,DeepSeek deepseek-chat)
- 呈现形态(v0.3.0 起):**文字游戏式人物对话**——每句台词带说话人,前端渲染为带名字/头像的对话气泡(主角右侧、NPC左侧、旁白居中),生成时逐行流式入屏;六个角色均有程序手绘 SVG 头像,后续可无缝替换为 AI 生成人物图

### 1.2 技术架构

```
浏览器(static 前端) → nginx(80,反代+安全头) → uvicorn/FastAPI(127.0.0.1:8000)
                                                      ├─ engine/(宪法/状态/导演/账本/流水线)
                                                      ├─ provider: Mock | OpenAICompat(DeepSeek云端)
                                                      ├─ data/sessions/*.json   会话存档
                                                      ├─ data/usage.jsonl       LLM用量埋点
                                                      └─ data/events.jsonl      玩家行为事件(v0.2.0新增)
```

- 技术栈:Python 3.11 / FastAPI / uvicorn / pydantic;前端原生 HTML+JS
- 推理不落地:所有 LLM 调用走 DeepSeek 云端 API,服务器只是转发+状态存储

### 1.4 数据资产(三类,均在 `data/`)

| 数据 | 文件 | 内容 | 用途 |
|---|---|---|---|
| 会话存档 | `sessions/s_*.json` | 玩家状态全量(数值/记忆/事件账本/结局) | 游戏续玩、体验指标 |
| 用量埋点 | `usage.jsonl` | 每次 LLM 调用 tokens/延迟/剧本 | 成本核算、质量监控 |
| 行为事件 | `events.jsonl` | 每请求事件:页面访问/开局/回合/复盘等,IP 加盐哈希脱敏 | 玩家行为分析(v0.2.0 新增) |

### 1.5 安全措施(v0.2.0 就位)

1. **API Key 零泄露面**:密钥只存服务器 `.env`(600 权限,仅 root),前端/接口/日志均无密钥;全项目 `grep sk-` 仅命中 `.env`;
2. **管理接口鉴权**:`/api/admin/metrics`、`/api/admin/events` 需 `X-Admin-Token` 请求头(令牌存 `deploy/env.server`,不入 git);
3. **IP 限流**:普通 API 60 次/分/IP,回合接口 20 次/分/IP,超限返回 429(防刷量=防盗烧 API 配额);
4. **行为数据脱敏**:IP 加盐 SHA-256 截断,不存原始 IP;User-Agent 截断 120 字符;
5. **nginx 安全头**:`X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy`;
6. 请求体上限 2M、LLM 超时 90~120s、异常降级 Mock。

### v0.3.1 — 人物头像图片(程序手绘SVG,零生成成本)(2026-08-28)
- 需求:给每个角色配一张人物图片嵌进对话气泡,但要求不消耗图片模型token;
- 方案:不调用任何图片生成模型,直接**代码手绘扁平风SVG矢量头像**(每角色一个文件,~2KB,浏览器原生渲染,可无限缩放),并按角色配上标志元素——林sir:警徽+下压眉(冷峻);葛姨:发髻+围裙+茶叶蛋+笑眼;小满:锯齿乱发+大眼睛+缺角怀表;老周:鬓角白发+钥匙串;阿禾:长发+微蹙眉;主角"你":剪影+金星(双剧本共用);
- 头像底色沿用各角色在界面中的确定性哈希色(speakerHue),与角色名配色一致;
- 前端:`app.js` 的 `AVATAR_IMAGES` 已登记全部 6 个角色路径,对话气泡自动显示图片头像(未登记的角色仍回退"首字彩色占位");
- 后续换成AI生成的人物图时,只需替换 `server/static/avatars/` 下的文件或改 `AVATAR_IMAGES` 路径(png/jpg/webp/svg 均可),代码零改动;

### v0.4.0 — 文字游戏式逐句播放 + 自动播放 + 选项频率提升(2026-08-28)
- 需求:像文字游戏(AVG)那样**每次只显示一句话**,用户点击或按空格才出现下一句;新增自动播放按钮,自动播放时速度放慢,只在需要用户选择时暂停;玩家的选项频率适当提高;
- 前端新增**逐句播放器 `Player`**(app.js 状态机 idle/typing/wait):场景对话行入队逐句显示——当前句打字完成后进入"等待推进",点击对话区或按空格推进(打字中点击=立即补全本句,再点=下一句);**全部行播完才渲染选项按钮**;流式到达的新行直接入队,选完选项后新场景无缝继续;
- 自动播放:顶栏新增「▶ 自动播放 / ⏸ 自动播放」切换按钮;播放速度按行放慢(基础1.6s+每字70ms,单行2s~5.5s),推进提示切换为"▶▶ 自动播放中";**遇到选项自动暂停**,玩家选择后新场景行流入即自动继续;手动点击只打断当前行的自动计时,不关闭自动播放;
- 推进提示:对话区底部 sticky 悬浮「▾ 点击或按空格继续」(pulse动画),仅等待状态显示;
- 选项频率提升:编剧提示词场景长度从 8~16行/300~600字 收紧为 **6~10行/250~450字**,并要求每场输出 **3~4个选项**——同样阅读量下选择点更密集;审查器阈值不变(仍按宪法 300~600字 ±50% 弹性校验);
- 兼容:存档回放的历史行仍即时渲染(不逐句),仅当前场景走逐句播放器;流式与最终剧本不一致时整体重播;
- 涉及文件:`server/static/app.js`、`server/static/index.html`、`server/static/style.css`、`engine/pipeline.py`、`README.md`、本文档;
- 测试:主套件 46 项全绿;headless Chrome 实测:首句单独显示→点击/空格逐句推进→自动播放约2.1s/句放慢→选项处自动暂停(1.5s无变化)→选择后新场景自动继续并再次停在选项处。
