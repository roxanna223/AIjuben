# Cursor 调研 04：角色小说模拟推进工具

> 日期：2026-08-26  
> 目标：选定角色后生成专属故事主线；角色间可有交集或平行宇宙；结合世界观、剧情、人物关系、目标与世界主脉络，生成小说正文。

---

## 一、结论先行

**产品形态已被验证；工程正解是「共享世界状态 + 多视角渲染」，不是每人一条互不相干的故事。**

组合两条成熟路线：

| 层 | 技术 | 作用 |
|---|---|---|
| 骨架 | ink / Twine / Arcweave / 大纲 JSON | 确定性、可测试、可分支 |
| 血肉 | LLM + Lorebook + 摘要链 | 散文、NPC 涌现、语气 |

平行宇宙 = **大选择点复制世界状态快照再分叉**（彩云小梦「蝴蝶标记」范式），不是事后改写历史。

---

## 二、需求拆解

| 子需求 | 关键点 |
|---|---|
| 角色专属主线 | 从世界年表截取与该角色相关事件带 → 个人大纲 |
| 交集 | 同一世界事件，多角色各有视角版本 |
| 平行宇宙 | 分支存档 / 快照分叉 |
| 重要角色 + 随机 NPC | 卡全量注入 vs 模板涌现后写回状态 |
| 真正写出小说 | 逐章生成，长篇不崩人设与伏笔 |

## 四、关键机制设计

### 4.1 管线

```
世界年表 + 世界状态（调研 03）
        │
        ▼
角色主线规划器：选定角色卡（调研 02）
  → 截取相关事件带 → 三幕/章节大纲
        │
        ▼
章节生成器：注入 world_bible + 角色卡 + 关系网 + 当前状态
  → 产出正文 + 章摘要 + 伏笔表更新
        │
        ▼
交集检测：时间地点相交 → 写共享事件，各线各写视角版
```

### 4.2 交集 vs 平行

- **交集**：世界状态唯一事实源；事件写一次，视角渲染多次。  
- **平行**：大选择（调研 05）触发 → 快照分叉 → 独立事件日志。  
- 技术：JSON 状态 + seed 随机 + append-only event log。

### 4.3 NPC 策略

- 重要角色：全字段 + `mes_example` 锚定语气。  
- 随机 NPC：模板生成 → 出场后写回世界成「次级角色」可复用。  
- 怪谈向：NPC 也有「已知规则列表」。

### 4.4 长篇一致性四件套

1. Lorebook 关键词注入  
2. 章节摘要链（近 N 章 + 向量召回旧章）  
3. 伏笔表（setup / payoff 状态）  
4. 规则/事实校验器（输出不得违反 numbered rules）

---

## 五、推荐落地（MVP）

1. **先不做完美引擎**：固定大纲 JSON + LLM 逐章生成（单角色）。  
2. 接入 world_bible + 角色卡 + 摘要链。  
3. 骨架稳定后再让 LLM 生成 ink，或导出到 Twine/Arcweave 调分支。  
4. 平行宇宙只在「大选择」点开快照，避免处处分叉爆炸。

### 风险

- 纯自由生成跑偏 → 必须大纲门禁。  
- 多线矛盾 → 共享状态，禁止各线私改世界。  
- 成本 → 便宜模型做摘要，大模型写关键章。
