## 二、每环一句话结论

| # | 模块 | 结论 |

## 三、公共基础设施（贯穿五环，优先建设）

1. **统一数据**：`world_bible` Schema + `chara_card_v2/v3` + `world_state` JSON  
2. **Lorebook 注入器**：关键词命中设定条目 → 注入上下文  
3. **一致性校验器**：输出不得违反编号世界规则；实体引用可解析  
4. **摘要链 + 伏笔表**：长篇连贯工程解  
5. **多档模型路由**：便宜模型摘要/打标，大模型规则推演/关键正文  
6. **状态快照**：大选择点可 fork（平行宇宙）

---

## 四、建议实施顺序

1. **01 + 02**（数据地基）  
2. **04 简化版**（单角色大纲→章节，先通体验）  
3. **05**（节点打标 + 节奏校验，让输出变成互动小说）  
4. **03 宏观层**（编年史引擎；微观智能体最后按需）

规则怪谈项目：知识状态表在 01 就预留。

## 五、总表：哪个环节需要什么、能做什么

> 下列「需要的东西」含：现成产品、开源仓库、提示词/Skill、自建模块。原则：**先能做到，再产品化**。

### 环节 01 · 世界观设定

| 需要的东西 | 类型 | 可以做的事 |
|---|---|---|
| **Cursor 访谈 Skill**（参考 everyday-writer Questioner） | Skill / 提示词 | 一次一问；自动补齐标 draft；矛盾指出；输出基本盘 |
| **WorldBible JSON Schema + 三态字段** | 自建数据 | 字段门禁；确认后冻结；导出给下游 |
| **Structured Output（API）** | 技术能力 | 强制合法 JSON，避免散文糊弄字段 |
| **Dunia Creation Wizard** | 产品 | 同设定快速生成并「玩一遍」压力测试 |
| **Inkfluence / Storyflow** | 产品 | 一键 bible 脚手架 / 画布查矛盾 |
| **World Anvil 模板** | 参考 | 抄成熟字段清单，不必用其 SaaS 当真相源 |
| **Loreum / Novelcrafter Codex** | 产品（中期） | 结构化存档与写作注入 |
| **gameforge-cli** | CLI 参考 | 访谈→JSON→校验→断点的工程范式 |
| **Lorebook（NovelAI/SillyTavern 机制）** | 机制蓝本 | 设定按需注入，防失忆 |

**本环产出物**：`world_bible.json` + `.md`（含 rules / taboos / opening / knowledge_state 预留）

### 环节 05 · 剧情节点控制与节奏

| 需要的东西 | 类型 | 可以做的事 |
|---|---|---|
| **节点分类器 Skill** | Skill / 提示词 | 对剧情打 `major` / `minor`；拒伪分支 |
| **大/小选择验收清单** | 规则文档 | 产品与生成双重验收（《黑相集》《日落黄昏时》《Episode》准则） |
| **节奏校验器** | 自建工具 | 按字数检测选择间距、开篇钩、高压连续章 |
| **字数节奏基线表** | 配置 | 小选择 500–1000 字；大选择 3000–8000 字；情绪点 150–300 字 |
| **ink / Twine / Arcweave** | 工具 | 试玩选择结构；确认链/属性累积等模式 |
| **短剧卡点公式** | 方法论 | 换算「何时拉扯用户心理」；信息差卡点形态 |
| **大选择多媒体槽** | 产品能力 | 配图/动效/音乐；明确「这是重要抉择」 |
| **状态 fork API** | 自建 | 大选择 → 世界快照分叉（接 03/04） |

## 六、跨环节「最小工具包」（若只选一套先开工）

| 优先级 | 先备齐 | 理由 |
|---|---|---|
| P0 | WorldBible Schema + 访谈 Skill | 没有冻结世界观，后面全空转 |
| P0 | chara_card_v2 + 角色生成 Skill | 人设标准现成，立刻可测 |
| P0 | 章节生成 + 摘要链 | 用户最先感知的「小说」体验 |
| P1 | 节点分类器 + 节奏校验 | 从小说变成互动小说 |
| P1 | 世界状态快照 | 大选择/平行宇宙前提 |
| P2 | 编年史规则引擎 | 大画面；可后置 |
| P2 | AI Town/Concordia 微观模拟 | 成本高，按需 |
| 对照用 | Dunia + SillyTavern + ink/Inky | 分别验证：可玩性 / 角色卡 / 分支骨架 |

## 七、主要风险（全项目）

1. 长篇一致性：Lorebook + 摘要链 + 伏笔表 + 状态表必须组合，单靠大上下文不够。  
2. 成本：微观多智能体是黑洞；严格限规模与时长。  
3. 选择疲劳：小选择宁少；用无选项紧张段填节奏。  
4. 人设模板化：强制缺陷/秘密/矛盾 + 压力 QA。  
5. 字段贪多：只收能制造剧情张力的字段。  
6. LLM 偷偷改规则：规则裁决必须在引擎/GM，不在散文生成层。
