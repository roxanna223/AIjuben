## 定位

互动小说创作工具链的**五环管线**：从自然语言生成世界观，到可玩、有节奏、可分支的互动小说正文。
**路线定位（已决策）：独立的 PlanB 新项目**，与 `ai-storyline/`（「歧路」）平行演进，互不修改。

## 五环结论与采纳（一句话 + 用什么）

| # | 环节 | 结论 | 采纳方案 |
|---|---|---|---|
| 01 | 世界观设定 | 无开箱产品；自建「访谈 + Schema 门禁」可行 | 访谈 Skill（参考 everyday-writer Questioner）+ WorldBible JSON Schema（三态字段：draft/confirmed/open）+ 门禁冻结 |
| 02 | 人物设定 | 现成标准最多的一环 | 直接采用 **chara_card_v2/v3**；关系网骨架驱动生成 + 压力 QA；扩展私有 `extensions` 字段 |
| 03 | 世界脉络 | 分层，不能拿纯 LLM 硬跑百年 | 宏观编年史（规则 YAML + LLM 只写叙事不改规则）→ 中观快照 → 微观智能体（≤50、仅关键片段）；规则裁决放 GM 层 |
| 04 | 角色小说 | 共享世界状态 + 多视角渲染 | 固定大纲 JSON + LLM 逐章生成；骨架（ink）确定性 + 血肉（LLM）；大选择点才开快照分叉 |
| 05 | 剧情节点 | 按「结果层次」分大/小选择；节奏套短剧数据换算 | 节点分类器（major/minor/伪分支打回）+ 节奏校验器 + 大选择多媒体反馈 |

## 贯穿五环的公共基础设施（先建最划算）

1. **统一数据**：`world_bible` Schema + `chara_card_v2/v3` + `world_state` JSON（可快照、可 diff、可 seed）
2. **Lorebook 注入器**：关键词命中 → 设定条目注入（防长篇失忆）
3. **一致性校验器**：输出不得违反编号规则；实体引用可解析
4. **摘要链 + 伏笔表**：长篇连贯性工程解
5. **多档模型路由**：便宜模型做摘要/打标，大模型写规则推演/关键正文
6. **状态快照器**：大选择点 fork（平行宇宙）

## 节奏基线（05 换算结论，起步参数）

- 开篇 50–150 字内抛钩；每 150–300 字一个情绪点（可无选择）
- 小选择间隔 500–1000 字；大选择间隔 3000–8000 字（每章 0–1 个）
- 连续高压 ≤2 章后必须喘息章；大选择后立刻兑现后果
- 小选择宁少勿多：互动小说是「阅读+决策」双负载，频率低于短剧刺激密度

## 风险 TOP

1. **长篇一致性**：任何单一机制都不够，必须 Lorebook+摘要链+伏笔表+状态表组合
2. **成本失控**：微观多智能体是黑洞 → 严格限 ≤50 agents、短时段
3. **选择疲劳**：小选择宁低勿高，用无选择紧张段填节奏
4. **人设模板化**：生成 prompt 强制缺陷/秘密/矛盾点 + 压力 QA
5. **字段贪多**：只收「能制造剧情张力」的字段，装饰性设定不进核心层
6. **LLM 偷偷改规则**：因果裁决必须在 GM/规则引擎，不在散文生成层
