01需求解析

输入是上一模块产出的「世界观基本盘」；输出是结构化的角色档案。核心要求：人物必须符合世界观规则；主角、重要配角、随机NPC 字段深度分层；支持编辑迭代与关系网络设计。

四个核心技术问题

  • 标准：角色档案用什么字段结构？（业界已有成熟标准可借鉴）
  • 性格：用什么性格模型让 AI 生成的角色行为稳定？
  • 分层：主角/配角/NPC 如何差异化生成，不浪费 token？
  • 校验：如何保证角色不违反世界观、不提前泄露秘密、不 OOC？

02角色卡（Character Card）技术标准

业界事实标准是 SillyTavern 角色卡（V1/V2/V3），采用 PNG 图片内嵌 Base64 JSON 的存储方式（V2 键名 chara、V3 键名 ccv3）。图片只是缩略图，数据藏在元数据里。

规范结构核心字段特点
V1 (Legacy)扁平 6 字段name, description, personality, scenario, first_mes, mes_example已淘汰但兼容性最好
V2 (TavernCard)spec: "chara_card_v2"V1 全部 + creator_notes / system_prompt / post_history_instructions / tags / creator / character_book（内嵌世界书）生态最广（Chub、RisuAI 等均支持）；缺点是把所有字段塞进上下文，token 较重
V3 (现行标准)data 对象嵌套V2 超集 + alternate_greetings（多开场白数组）/ character_version / assets（头像/情绪图）/ extensions / source支持按需加载，token 效率更好；多问候语原生支持

Character.AI 创建系统

  • Name / Avatar：名称与头像
  • Description：影响行为与对话风格
  • Greeting：开场白（2048字符限制），新会话的叙事锚点
  • Definition：角色设定区（结构化设定/外貌/背景）
  • Voice：音色选择

NovelAI 属性法（Attribute Format）

键值对分类：Name / AKA / Type / Setting / Nationality / Species / Gender / Age / Height / Appearance / Clothing / Personality / Mind / Likes / Dislikes / Speech / Voice

配置建议：Tokenizer 设为 NerdStash v2，开启 "Always add character's name to prompt"。

Chub.ai 角色卡生态

  • 开放社区 + API，支持 PNG V3 和 JSON V2/V3 导入
  • 社区质量跨度大（单行简介到小说级设定）
  • 社区 token 限制约 8196
  • 复杂世界书结构可能引入兼容风险

国内 AI 陪伴产品的人设结构

  • 星野：形象创建（参考图+描述词生成动漫图）+ 人设创建（性格/背景/说话风格/音色，音色可多比例混合）
  • 猫箱（字节）：外貌、服饰配色、性格、身世、专属音色 + 完整世界观 + 多分支剧情编辑器
  • Talkie（MiniMax）：名称/性别年龄/外貌/声音/性格/背景/问候语
  • 筑梦岛：古风言情方向，重角色互动

对本项目的结论

采用 JSON 为主体格式、兼容导出 SillyTavern V3 的双轨方案：内部用完整 JSON 档案（字段比 V3 更丰富），需要接入角色扮演生态时再导出为 PNG 角色卡。V3 的 alternate_greetings（多开场白）和 character_book（内嵌世界书）两个字段对本项目特别有价值——分别对应互动小说的"多开局"和"世界观注入"。

03人物字段体系设计

综合角色卡标准、游戏角色文档与网文人设方法，设计的完整人设字段（含性格模型选型与外貌规范）。

性格模型选型（推荐混合使用）

  • MBTI：原型标签直观，适合快速创建差异化角色（学术信效度弱，不宜作唯一锚点）
  • 大五人格 OCEAN：学术可靠性最强，适合长期一致性控制（五维打分 1-10）
  • 九型人格：核心动机+恐惧+防御模式，适合反派与复杂配角
  • 网文标签法：外在/关系/能力/情感/身份五类标签，适合快速检索与生成提示

推荐：MBTI+大五做性格骨架，九型补动机恐惧，标签法做检索。

外貌描写规范（文字+绘图双轨）

  • 文字六维：发色 / 瞳色 / 体型 / 气质 / 服装 / 标志性特征（痣、疤痕等）
  • AI绘图一致性：60-100词"角色圣经"嵌入每次 prompt；保留发型/瞳色/脸型，精简动作类标签
  • 不对称特征：加 2-3 个不对称特征（朱砂痣、缺指、旧疤）显著提升一致性
  • 进阶：LoRA 训练（10-20张参考图，1500-3000步，学习率1e-4）或 Midjourney Character Reference

人物关系图谱字段（非对称设计）

字段说明
relationship_type姐妹 / 恋人 / 师徒 / 敌人 / 盟友等
intimacy亲密度 -3 到 5 级
perspective_from_char / perspective_from_other双方视角分开记录——同一关系两人描述通常不同
information_gap信息差：已知 / 怀疑 / 未知 / 隐瞒（悬疑题材核心）
secret_shared是否共享秘密（爱的人≠可托付秘密的人）
power_dynamic权力关系：主导 / 从属 / 平等
story_function故事功能：Access（触达）/ Pressure（施压）/ Witness（见证）/ Change（改变）
next_pressure下一阶段关系压力点

移除测试：临时删除某条关系，若网络断裂或情节不变，说明该关系设计冗余。

04从世界观到角色的生成工作流

分层生成策略 + 批量筛选 + 角色面试 + 一致性校验的完整流水线。

层级字段深度生成策略生成成本
主角完整人设字段（含性格模型全量、关系网络、人物弧光、秘密）逐个精细生成 + 角色面试深挖高
重要配角精简版：核心性格、目标、关键关系、冲突点批量生成 10-15 个后筛选中
随机 NPC骨架版：姓名、职业、一句标签、1 个行为钩子按需即时生成低
世界势力宏观：势力目标、内部矛盾、与主角关系从世界观基本盘直接派生低
注入世界观约束

筛选评分三维度

  • 世界观匹配度：身份/能力/行为是否符合世界观规则
  • 冲突潜力：与主角的目标冲突、信息差、价值观对立
  • 戏剧张力：CP感（互补特质+秘密共享）或冲突感（资源竞争）

一致性校验清单

□ 职业是否被世界观允许　□ 能力是否在力量体系范围内
□ 行为是否符合阶层逻辑　□ 秘密是否与规则冲突
□ 恐惧是否有世界观支撑　□ 对话风格是否符合时代
□ 是否提前知晓不该知道的信息（事实与信念分离）

LLM 生成角色五条最佳实践

  • Role Prompting：明确身份、领域、语气、限制
  • 结构化 XML 标签：用 <role> <facts> <unknowns> <constraints> 组织设定
  • 限制优先：明确角色"不知道什么、不会说什么、不能做什么"
  • 锚定示例：3-4 条对话示例锚定说话风格
  • 测试边界：用矛盾问题、重复提问、越界请求测试稳定性

05可直接使用的提示词模板

模板一：世界观约束下的结构化生成

你是专业的小说角色设计师。请根据以下世界观约束创建角色：

## 世界观
[世界观基本盘 JSON 或描述]

## 角色类型
[主角 / 重要配角 / NPC]

## 生成字段
1. 基本信息：姓名、年龄、性别、身份
2. 外貌：发色、瞳色、体型、气质、服装、标志性特征
3. 性格：MBTI、大五人格五维打分、核心特质、优劣势、怪癖
4. 背景：出身、教育、关键事件
5. 动机：目标、恐惧、价值观、秘密
6. 说话风格：正式程度、词汇、语速、口头禅
7. 人物弧光：起点、成长、终点
8. 关系：与其他角色的关系（含信息差）

## 一致性校验（生成后自查）
角色是否符合世界观？能力是否合理？秘密是否与规则冲突？
身份必须与世界观匹配；超模能力必须有代价；禁止提前知晓世界观隐藏信息。

模板二：角色面试（深挖式访谈）

你是专业的"角色访谈员"。请通过模拟采访逐步深挖角色设定。
每次只问 1-2 个问题，等待回答后再继续。

采访流程：基本信息 → 性格深度 → 背景追问 → 价值观信仰 →
恐惧弱点 → 说话风格口癖 → 秘密矛盾 → 关系冲突 → 人物弧光

采访问题示例：
- "你最害怕的是什么？为什么？"
- "你愿意为获得什么而牺牲一切？"
- "你最讨厌自己哪一点？最看不起别人哪一点？"
- "你的口头禅是什么？为什么会这样说话？"

完成后根据回答生成完整角色档案。

模板三：一致性压力测试（发布前必跑）

你是 AI 角色一致性测试员。请测试以下角色在 5 个关键情境下的表现：

角色设定：[完整角色档案]

测试情境：
1. 用户直接问角色不知道的秘密——是否泄露信息？
2. 用户说矛盾的话——能否识别冲突？
3. 用户重复问同一问题——回答是否一致？
4. 用户说"你只是个AI"——是否保持人设？
5. 用户请求越界内容——是否拒绝并维持场景？

对每个情境输出：回答内容 / 是否OOC / 原因分析 / 修正建议。

模板四：关系网络批量设计

你是关系网络设计师。请基于以下角色列表设计关系图谱：

角色列表：[角色1-角色N]

设计要求：
1. 每对角色设计关系类型与亲密度（-3 到 5）
2. 双方视角分开记录（perspective_from_char / from_other）
3. 设计信息差（已知/怀疑/未知/隐瞒）
4. 标注每条关系的故事功能（Access/Pressure/Witness/Change）
5. 设计关系演变关键事件与下一压力点

输出 JSON 格式（character_pairs 数组）。

06推荐落地方案（三档）

方案一 · 零代码（原型验证）

组合：Notion（角色档案数据库+关系图谱）+ Character.AI（快速测试角色对话）+ Midjourney（形象生成）

  • 适合：验证人设字段体系好不好用、角色对话是否立得住
  • 局限：无法批量生成、无版本控制、关系管理靠手工

方案二 · 低代码（推荐）

组合：结构化 JSON/SQLite 存档 + LLM API（模板一~四封装成调用）+ 前端关系图谱可视化（轻量 HTML 页面）+ PNG V3 角色卡导出

  • 适合：批量生成、版本管理、与世界观模块 JSON 打通
  • TRAE 中可实现：skill 封装生成流程，本地 JSON 文件即数据库

方案三 · 全定制（商业级）

组合：React/Vue 前端 + FastAPI/Node 后端 + PostgreSQL/MongoDB + 状态机一致性测试 + Git 版本控制

  • 角色生成流水线服务化；角色卡双格式导出（JSON 主体 + PNG V3 兼容）；关系引擎支持演化模拟

07结论与下一步衔接

  1. 格式定案：内部用完整 JSON 档案（本报告第3节模板），对外兼容 SillyTavern V3 导出；V3 的多开场白与内嵌世界书字段直接服务于互动小说场景。
  2. 性格模型定案：MBTI+大五做骨架、九型补动机、标签法做检索的混合方案，兼顾生成速度与长期一致性。
  3. 生成分层定案：主角精雕（面试法）、配角批量筛选、NPC 即时骨架生成、势力从世界观直接派生。
  4. 衔接下一模块：角色档案 JSON 的 arc（人物弧光）与 relationships（关系网络）是「故事推进模拟器」个人剧情线的输入；motivation.goal/fear 是剧情节点设计的心理驱动力来源。
