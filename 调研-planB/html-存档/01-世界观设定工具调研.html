01需求解析：这个工具要做什么

目标工作流：用户用一句自然语言描述想法，AI 生成完整世界观，自动补齐缺失部分，通过多轮对话不断完善，最终输出一套固定格式的"基本盘"字段——字段填完即代表世界观相对完整，可进入下一阶段（人物设定 / 剧情推演）。

自然语言描述
→
AI生成完整世界观
→
自动补齐缺失项
→
多轮沟通迭代
→
完整性审计通过
→
输出基本盘JSON

四个核心技术问题

  • 生成：如何从模糊想法生成结构化、字段齐全的世界观？
  • 补齐：AI 如何识别缺失字段——自动填默认值，还是主动提问？
  • 迭代：多轮修改如何保持一致性（不冲突、不漂移）？
  • 输出：固定格式怎么定？填完哪些字段才算"世界观完整"？

关键结论

  • 没有现成产品完整覆盖需求——国际工具偏"写作辅助"（面向作者手动维护），国内工具偏"大纲生成"（一次性输出），都缺少"多轮迭代补齐 → 固定格式验收"的闭环。
  • 最值得借鉴的机制：Sudowrite 的 Braindump（想法倾倒→自动结构化）、NovelCrafter 的 Codex（活体wiki按需注入）、SillyTavern 的关键词触发（Lorebook技术）。
  • 推荐自建：用通用 LLM + 结构化提示词 + 本地知识库自建工作流（见第6节落地方案）。

03核心交付物：世界观"基本盘"字段体系

综合 World Anvil 模板体系、Sanderson 世界观方法、SummonWorlds 12部分70+问题模板、D&D 设定文档结构，提炼出适合互动小说（女性向题材）的 11 大类字段。字段填完 = 世界观完整。

#字段类别子字段必填说明
1基本信息风格 / 年代朝代 / 故事背景一句话✓宫斗·甜宠·悬疑·规则怪谈·仙侠等；架空古代/现代/近未来
2主角信息姓名 / 年龄身份 / 外貌特征 / 性格标签(3-5个) / 核心欲望 / 核心恐惧✓欲望与恐惧驱动全部剧情
3核心冲突表面冲突 / 深层冲突 / 反派或对立势力 / 力量体系✓力量体系需含机制、等级、代价
4世界设定地理环境 / 社会规则 / 文化习俗 / 历史事件 / 势力格局 / 货币经济前三项✓等级、礼仪、禁忌、潜规则
5故事开头开头场景 / 开头冲突 / 第一个钩子 / 可选场景1-3✓可选场景用于互动分支起点
6人物关系核心关系网 / 关系状态✓好感度、敌对、未知、依赖
7规则系统规则或禁忌 / 违规后果 / 代价限制✓规则怪谈类核心字段
8情感线主线情感走向 / 配角情感线主线✓女性向题材关键
9关键物品关键道具 / 秘密信息✓推动剧情的麦高芬与隐藏秘密
10故事基调基调氛围 / 主题基调✓"甜中带虐""悬疑压迫"等
11名称体系命名规则可选地名、人名、组织名的命名风格

完整性检查清单（字段填完即验收通过）

□ 风格、年代、背景一句话是否明确　　□ 主角姓名/身份/外貌/性格/欲望/恐惧是否齐全
□ 表面冲突与深层冲突是否区分清楚　　□ 反派或对立势力是否明确
□ 力量体系是否有机制 + 等级 + 代价　　□ 地理/社会规则/文化是否覆盖
□ 历史事件、势力格局是否为当前故事服务　□ 开头场景/冲突/第一个钩子是否明确
□ 是否设计了 2-3 个可选开头场景　　□ 核心人物关系是否建立
□ 规则禁忌与违规后果是否明确　　□ 情感主线是否清晰
□ 关键物品与隐藏秘密是否就绪　　□ 基调是否全文一致

04多轮迭代完善机制设计

来源：r/worldbuilding 社区的"Play 20 Questions With Your World"方法论，改造为互动小说适用的问答体系。

机制一：20个问题问答法

把世界观问题设计成"角色会问的问题"，而不是设定清单：

  • 主角所在的地方有什么特殊限制？
  • 谁是最有影响力的人？有没有秘密组织？
  • 地图上有绝对不能去的地方吗？
  • 这个世界最奇怪的规则是什么？
  • 主角情绪最脆弱的时刻是什么？
  • 主角最信任谁？最不信任谁？
  • 如果世界突然消失，主角会失去什么？

机制二：AI 完整性审计员

每轮对话后让 AI 按 11 大类检查，每项标注状态：

  • 【完整】肯定并锁定
  • 【缺失】提出 3-5 个引导问题（不一次问太多）
  • 【需补充】给出选项让用户确认

同时检测矛盾：人物关系、力量体系、规则代价、时间线四处是矛盾高发区。

机制三：补齐策略分流

  • 次要设定（节日/饮食/货币/地名）→ AI 自动填默认值，标注"建议值"可修改
  • 核心设定（主角/核心冲突/规则代价/情感线）→ AI 给选项，用户确认式补全
  • 增量更新 → 每新增关键设定同步更新基本盘

机制四：一致性维护

  • 版本管理：记录变更原因 + 内容 + 影响范围
  • 增量更新：只记录变化，不重写全量
  • 冲突检测：AI 扫描时间线/力量体系/人物关系矛盾
  • 引用链：人物、地点、势力用固定名称，便于跨文本追踪

05可直接使用的提示词模板

三套核心模板：初始生成 → 审计迭代 → 自然语言转结构化。

模板一：初始世界观生成（Master Prompt）

// 用于第一轮：从用户想法生成完整基本盘
你是专业的世界观构建专家，擅长宫斗、甜宠、悬疑、规则怪谈、仙侠等女性向互动小说题材。

请根据以下用户输入，生成完整的"基本盘"字段，输出为 JSON 格式。

用户输入：
风格：{风格}　年代：{年代}　一句话背景：{背景}
主角：{姓名}，{年龄身份}，{外貌}，{性格}
核心欲望：{欲望}　核心恐惧：{恐惧}

请输出 11 大类：基本信息 / 主角信息 / 核心冲突 / 世界设定 / 故事开头 /
人物关系 / 规则系统 / 情感线 / 关键物品 / 故事基调 / 名称体系

要求：
- 每个字段都要有具体细节，禁止写"由你决定"
- 缺失信息基于输入合理补全，并标注"建议值"
- 中文输出

模板二：审计与冲突检测（迭代轮使用）

// 每轮修改后运行，驱动多轮完善
你是世界观完整性审计员。请检查以下世界观基本盘，按 11 大类逐项评估。

请输出：
1. 每个字段状态：【完整】【缺失】【需补充】
2. 缺失字段的原因
3. 针对缺失字段提出 3-5 个引导问题（先聚焦 3 个最关键缺失项）
4. 检查前后矛盾：人物关系 / 力量体系 / 规则代价 / 时间线

世界观内容：{粘贴当前世界观JSON}

要求：对已完整字段给出肯定；对矛盾字段给出具体修改建议；输出 JSON 格式。

模板三：自然语言 → 结构化 JSON

// 用于用户随口描述的即时转化
请将以下用户自然语言描述，转化为世界观"基本盘"JSON 结构。

用户描述：{粘贴用户自然语言描述}

要求：
- 未提供字段基于输入合理补全并标注"建议值"
- 输出 JSON，不输出额外解释
- 描述明显不完整时，在 missing_fields 数组中列出缺失项

06推荐落地方案（三档）

按投入成本从低到高三档方案，均为可直接执行的组合。

方案一 · 零代码（快速验证，1天内可跑通）

工具组合：彩云小梦（世界设定词条）+ 墨狐AI（世界观大纲）+ Kimi/豆包（多轮问答补齐）+ Notion/飞书文档（人工维护基本盘）

  • 适合：先验证字段体系是否好用，跑通一个完整世界观的生成流程
  • 局限：无自动触发注入、无版本管理、一致性靠人工

方案二 · 低代码（推荐起步，平衡效果与成本）

工具组合：Sudowrite Story Bible（Braindump→结构化）+ World Anvil（结构化模板）+ Obsidian 本地知识库 + Custom GPT/Claude Projects（自然语言转 JSON 助手）

  • 适合：中长期维护世界观与人物关系
  • 核心是把第3节的 JSON 模板做成 Custom GPT 的系统提示词 + 输出格式约束

07结论与下一步衔接

  1. 自建工作流是最优解：现有产品均不完整覆盖"迭代补齐→固定格式验收"闭环，但机制可拼装——Sudowrite 的 Braindump + NovelCrafter 的 Codex + SillyTavern 的关键词触发。
  2. 基本盘 11 大类字段体系是本模块核心交付物，JSON Schema 已就绪，可直接作为后续模块（人物生成、世界推演）的输入标准。
  3. 多轮迭代采用"审计员角色 + 分流补齐 + 版本管理"三机制，防止 AI 一次问太多或自作主张改核心设定。
  4. 衔接下一模块：基本盘 JSON 中的 world_settings（势力/规则）和 character_relationships 是「人物设定模拟器」的输入；rules_system 是「故事推进模拟器」规则引擎的输入。
