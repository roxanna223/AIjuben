01需求解析

本模块要建立世界观的主线运转脉络（非单个角色视角）：一套符合世界观规则的运算体系，推演世界从起源到 N 年后的发展，以"大画面"形式输出世界史，供后续模块选择角色切入个人剧情。

编年史生成
→
剧情钩子提取

四个核心技术问题

  • 规则遵守：如何让推演严格遵守世界观规则（如规则怪谈的规则体系），不被 LLM 自由联想带偏？
  • 长程稳定：LLM 连续推演容易"漂移"（语义漂移/因果断裂/规则漂移），如何对策？
  • 大画面：如何以编年史/史书体视角（而非角色视角）生成世界史？
  • 衔接：推演出的世界大事记如何转化为可交互的个人剧情入口？

02学术前沿与开源项目

LLM 多智能体模拟是近三年最活跃的方向，以下按"对本项目的参考价值"梳理。

Stanford Generative Agents（2023）奠基之作

25 个 agent 在 Smallville 小镇自主生活，核心架构：

  • Memory Stream 记忆流：自然语言记录全部经历，按需检索
  • Reflection 反思：从经历抽象出高层判断
  • Planning 计划 → Action 行动

涌现出人际关系、信息传播、群体活动。启示：适合关键人物/势力的微观模拟，不适合全量推演。

Project Sid（Altera，2024）文明涌现

10–1000+ agent 的 Minecraft 文明模拟，PIANO 架构（多输出流并行协调）。涌现现象：专业化分工、投票修宪、市场与税收、宗教传播、平行城镇政策分化。启示：借鉴"角色-规则-文化-制度"演化逻辑，但成本高不宜默认采用。

OASIS（CAMEL-AI，2024-25）百万级社交

最高约 100 万 agent 的社交媒体模拟（关注/评论/转发+推荐系统）。启示：适合舆论扩散、群体极化建模，非世界史引擎。

AgentSociety（清华，2025）社会模拟平台

LLM-native 城市社会模拟，模块化环境热插拔、多种推理模式（CodeGen/ReAct/Plan-Execute）。启示：借鉴"环境模块化+agent+规则执行"架构，抽象出城市/势力/人口/制度/事件模块。

Human History Simulator最接近本项目

LLM 多 agent 文明推演模拟器（开源可下载）：20 纪元、3600+ 年、1400+ 文明，经济/军事/外交/文化同步推算。机制：AI 编排器聚类区域生成事件 + 外交贸易 agent 双边推理 + 交互式世界地图，同一起点可产生不同历史走向。

其他参考项目

  • Agentopia：100 agent × 10 模拟年的长程社会生活
  • WarAgent：LLM 模拟世界大战与冲突（含战国时期）
  • Agent Drift / ReflectiChain：长程漂移问题与反思对策研究——直接回应本项目"长程稳定性"痛点
  • CAMEL / MetaGPT：通用多 agent 框架（后者偏软件开发流程）

03世界时间线推演方法论

两条技术路线：分时代分段推演（状态文件传递）与事件链因果推演（状态机驱动）。

游戏参考机制可借鉴点
Dwarf Fortress世界生成器：先生成地形/气候/生态，再推演文明兴衰、战争、英雄与巨兽，按"时代"推进层叠结构：世界基底 → 历史事件 → 文明 → 人物
Crusader Kings角色驱动历史：角色属性/婚姻/继承/野心，历史由角色行为涌现关键人物作为"可被事件触发的实体"参与世界史
RimWorld AI Storyteller三种讲述者控制叙事节奏：Cassandra（挑战-喘息循环）/ Phoebe（长期平静）/ Randy（随机）世界史叙事节奏设计：发展期→危机→全面危机→重建→新纪元
《文明VII》纪元机制历史分层呈现：古典/探索/摩登时代各有独立科技树、危机与叙事弧阶段推进而非线性年份：按社会形态跳跃进入新纪元

方法一：分时代分段推演提示词

// 每次只推演一个时代，时代总结写入世界状态文件作为下一时代输入
【世界观基础设定】{背景设定} {核心规则} {初始世界状态}
【当前时代】：{纪元名称}，时间范围：{起始年}-{结束年}
【时代特征】：{政治/经济/技术/文化特征}
【前代世界状态摘要】：{上一时代的关键事件、势力变化、资源变化、规则状态}

【推演任务】
1. 按年或按年代推进，每次输出 5-10 个年度事件
2. 事件格式：{年份} | {事件类型} | {影响范围} | {因果链}
3. 必须遵守规则：{规则约束清单}
4. 必须记录世界状态变化：资源、势力、人口、宗教、技术、外交

【输出格式】
时代：{纪元名称}　时间范围：{起}-{止}
年度事件：
- {年份}：{事件描述}（因果链：{前因}→{事件}→{后果}）
世界状态变化：势力/资源/宗教/技术/外交…
时代总结：{该时代对下一时代的影响}

方法二：事件链因果推演提示词（JSON输出）

// 从当前世界状态出发，生成带因果链的事件，事件间必须有因果或冲突关系
【当前世界状态】：{世界状态JSON摘要}
【当前年份】：{year}
【规则约束】：{世界规则 / 势力规则 / 禁忌规则 / 隐藏规则}

【推演任务】生成 {N} 个本年度事件，每个事件包含：
事件名称 / 触发原因 / 涉及势力人物 / 直接后果 / 对世界状态的影响
禁止生成违反规则体系的事件。

【输出格式】
{
  "year": year,
  "events": [{ "id": "E-xxx", "name": "...", "type": "...",
    "actors": ["..."], "cause": "...", "effect": "...",
    "world_state_change": {...} }],
  "next_state": {...}
}

"初始条件 + 规则 → 推演 N 年"的可行性结论

  • 短程可行（10-50年）：结构化状态文件 + 规则约束，推演稳定
  • 中程需干预（50-200年）：需要事件触发器、时代转折点、阶段性总结
  • 长程不推荐一次性推演：必然漂移。对策：分阶段推演、强制 JSON 输出、规则前置注入、时间锚点（强制转折事件）、三系统互相校验（世界状态×事件日志×规则约束）
  • 规则怪谈世界尤其要限制自由演化：规则必须显式约束，不能依赖 LLM 联想

04世界规则系统设计（规则怪谈方向）

规则的机器可读表达 + 优先级分层 + LLM 推演的规则约束机制。

规则怪谈创作方法论

  • 日常场景：规则发生在熟悉场所（公司/学校/医院）
  • 语言严谨：表述越正式，认知冲突越强
  • 掺杂反常识偏差：规则合逻辑但结论反直觉
  • 不明说罚则：通过后果暗示恐惧
  • 暗线汤底：规则背后有隐藏真相
  • 污染机制：规则可通过接触/观察/记忆"感染"
  • 与本能相悖："不要回头""不要相信眼睛"

规则四层结构

  • 明面规则：规则文本直接呈现
  • 隐含规则：通过规则间的矛盾暗示
  • 反向规则：与明面规则相反但更深层
  • 污染规则：违反后改变认知/规则效力/世界观结构

设计原则：自洽性（单条可解释）、冲突性（多条部分矛盾制造撕裂感）、认知不可靠（规则可被篡改）、代价不可逆。

规则优先级分层（P0-P4）

P0 世界底层物理规则（不可违反） P1 社会制度规则（法律/阶级/政治） P2 宗教/神秘规则（仪式/禁忌） P3 规则怪谈规则（明面/隐含/反向） P4 隐藏规则（最终真相）

规则的机器可读表达

// 规则条目（状态机 + 事件系统 + 优先级 + 条件触发）
{
  "id": "RULE-001", "name": "规则名称",
  "tier": "explicit | implicit | reverse | pollution",   // 明面/隐含/反向/污染
  "condition": "触发条件", "action": "触发行为",
  "priority": 1,
  "conflicts_with": ["RULE-002"],   // 冲突规则（撕裂感来源）
  "override_by": ["RULE-005"],     // 被哪些深层规则覆盖
  "effect_on_state": {...}
}

// 触发条件类型
时间触发（特定年份/世代/事件）· 条件触发（势力/资源/人物状态达阈值）
规则冲突触发（两条规则同时生效）· 污染触发（认知污染超阈值）

LLM 推演的规则约束模板

【世界规则约束】
P0：{底层物理规则}　P1：{社会制度规则}
P2：{宗教神秘规则}　P3：{规则怪谈规则}　P4：{隐藏规则}

【当前生效规则】{RULE_ID}: {规则描述}

【禁止事项】
- 不得生成违反 P0 规则的事件
- 不得绕过 P1 规则建立新制度
- 不得忽略 P2/P3 规则的冲突机制
- 不得直接揭示 P4 隐藏规则，除非满足触发条件

【输出要求】必须输出结构化 JSON，不得输出自由文本。

规则约束五策略（防止 LLM 漂移）

  • 规则注入时机：每次生成前注入当前生效规则列表
  • 输出校验：LLM 输出必须为 JSON 并通过 Schema 校验
  • 规则校验器：确定性代码检查输出是否违反规则，违规则强制重新生成
  • 冲突检测：输出导致规则冲突时修正
  • 分层推理：先算世界状态变化（代码），再让 LLM 生成叙事描述

06大画面叙事生成与剧情钩子提取

编年史/史书体生成技巧

  • 历史学家视角：LLM 扮演"世界史编纂者"而非角色
  • 宏观语言："某年，某地，某势力崛起/衰落"句式
  • 多视角拼合：同一事件记录不同势力版本，制造"史料感"
  • 不确定性：争议事件保留多版本——"A称……，B称……"
  • 因果完整：每事件含前因、经过、后果、格局影响

结构参考：编年体 → 纪传体

  • 编年体（按时间记事）：适合世界观主线推演——本模块产出
  • 纪传体（按人物记生平）：适合个人剧情——下一模块（角色小说模拟）消费
  • 《冰与火之歌》多POV：多线并行最终交汇，每角色有信息边界
  • 《三体》时间跨度：大历史直接作用于人物命运

剧情钩子提取流程（世界史 → 互动剧情入口）

世界史事件
→
提取危机/冲突/异变
→
关联关键人物
→
标注规则触发条件
→
生成POV角色档案
→
个人剧情钩子

五类钩子来源：①危机事件（事件日志中"危机/冲突/异变"类型）②人物关联（事件关键人物转POV角色）③规则触发（规则怪谈事件转为"探索/破解规则"剧情）④势力变化（加入/背叛/战争/联盟）⑤信息差（不同势力对同一事件的不同记录 → 悬疑剧情）。

编年史生成提示词

你是一位世界史编纂者，正在记录{纪元名称}时代的历史。

【背景】：{世界背景}　【当前时间】：{年份}　【关键事件】：{事件列表}

请以编年史体例撰写：
1. 正式、客观的史书语言，使用宏观句式（避免个体情绪）
2. 每个事件包含完整因果链
3. 记录对世界格局的影响
4. 对不同势力的视角保持平衡（争议事件保留多版本："A称……，B称……"）
5. 总结该事件对下一时代的影响

输出格式：
---
{年份}：{事件名称}
{客观叙述起因、经过、结果}
影响：{对世界格局的影响}
---

07三方案对比与推荐路线

第一阶段 MVP（1-2周）：方案A

单 LLM 多轮推演：世界状态 JSON 传递 + 事件日志 + 时代分段推演，输出结构化 JSON。先验证"给定世界观 → 产出可用世界史"的完整链路。

第二阶段 增强（3-4周）：升级方案C

加入规则引擎：规则系统 + 冲突检测 + 事件触发器 + 规则校验器。LLM 只负责叙事，状态变更走确定性代码。

第三阶段 扩展（2-3周）：混合架构

对关键势力/关键人物引入 agent（宏观规则引擎 + 关键人物 agent），保持世界状态 JSON 统一接口。参考 Generative Agents 的记忆流-反思机制与 Project Sid 的制度演化逻辑。

第四阶段 产品化

前端世界史可视化（Aeon Timeline / Campfire Timeline / 自研时间轴）+ 个人剧情入口 + 剧情钩子自动提取。TRAE 落地路径：Python 脚本管状态/日志/规则校验 + LLM API 生成叙事 + Skill 封装"输入世界观 → 输出世界史+状态+钩子"。

核心结论

  • 推荐路线 A → C → 混合：不要一上来做多 agent（成本高、可控性差），先单 LLM 跑通，再加规则引擎保证一致性，最后按需引入 agent。
  • 世界状态 JSON 是本模块的核心资产：它是后续所有模块（角色剧情、互动节点）的共享事实源。
  • 规则校验必须用确定性代码：LLM 自查不可靠，规则违反检测要靠 rule_engine.py 而非提示词。
  • 衔接下一模块：编年史事件 + 剧情钩子 + 世界状态中的关键人物 → 「角色小说模拟推进工具」的输入。
