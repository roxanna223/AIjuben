01需求解析

本模块是面向单个角色的小说生成引擎：用户选定某个角色（含重要角色与随机NPC）后，结合世界观、大世界剧情主脉络、人物关系与角色目标，生成该角色专属的故事主线。不同角色的主线可产生交集（引用同一世界事件的不同视角）或平行宇宙（关键选择分岔出世界线），最终以小说文本形式输出。

用户选定角色
→
载入角色卡+世界状态+主脉络
→
生成角色主线大纲
→
逐章生成小说文本
→
选择/事件回写状态
→
交集/分岔处理

四个核心技术问题

  • 主线差异化：同一世界观下，不同角色的主线必须明显不同——视角、目标、路径、叙事风格都要"人各有命"，而非同一剧情换主角名。
  • 交集与平行宇宙：多角色并行推进时，如何共享世界事件、如何在关键选择处分岔世界线、分岔后如何管理状态与剧情？
  • 长篇一致性：生成数万字后，角色性格/口癖不变、世界观规则不崩、伏笔能回收——LLM 长程生成最痛的三个坑。
  • NPC动态生成：随机NPC按需出现，要有"路人感"又不能与既有设定冲突，还要支持"转正"（从路人升级为重要角色）。

输入依赖：调研1的世界观基本盘、调研2的角色卡体系、调研3的世界状态/编年史/剧情钩子。本模块产出：角色线档案 + 章节文本 + 更新后的世界状态，供调研5的剧情节点控制模块插入选择点。

长篇叙事生成的学术谱系（按参考价值排序）

Re³（EMNLP 2022）递归重提示

Plan → Draft → Rewrite → Edit 四模块：先计划后写作，用递归重提示维持长篇连贯，情节连贯性重排序 + 事实一致性编辑。启示：两阶段（大纲→正文）与"写后修订"流程的鼻祖。

DOC（ACL 2023）细纲控制

Detailed Outliner 逐层细化大纲 + Detailed Controller 约束正文贴合大纲，显著提升长故事连贯性与多样性。启示：层级大纲（主线→章节→场景）+ 正文与大纲的对齐校验，是本模块生成流程的直接蓝本。

RecurrentGPT（2023）无限长文本

用语言模拟LSTM递归：每步生成短记忆摘要 + 下一步计划，作为下一步输入，实现任意长度交互式生成。启示：逐章推进时维护"滚动摘要+下章计划"状态，是长篇连载不漂移的关键机制。

Dramatron（2022）层级共创

自顶向下：log line → 角色描述 → 情节点 → 场景 → 对话，逐层人工可干预。启示：世界→角色→章节→场景→正文的层级生成链，每层允许用户介入修改。

IBSEN（2024）导演-演员协作

Director-Agent 生成剧情大纲，Actor-Agent 扮演各角色推进剧情，人类可随时介入。启示：与本模块"主线大纲（导演）+ 角色扮演生成（演员）"的双层架构高度同构。

MAGNET / ATLAS（2026）多智能体角色驱动

MAGNET：多个角色Agent基于共享世界状态与演化的故事目标提出行动，生成长篇叙事；ATLAS：图式一致性检测，比对当前场景与既往场景的世界状态识别矛盾。启示：共享世界状态=本模块交集机制的理论支撑；ATLAS式一致性校验可用于自动审稿。

Character-LLM（2023）/ Human Simulacra（2024）

Character-LLM 用"经历重构+上传+保护性经历"训练角色扮演Agent；Human Simulacra 用情绪Agent/思考Agent维持人格一致。启示：重要角色可沉淀"经历语料"强化扮演；轻量场景用提示词即可。

The Drama Machine（2024）

LLM Agent模拟角色发展与戏剧性社交场景。启示：角色弧光（性格随经历演化）可以作为状态字段显式管理，而非隐式期待LLM自己记住。

谱系结论

  • 共识路线：大纲先行（Re³/DOC/Dramatron）+ 递归状态（RecurrentGPT）+ 角色Agent化（IBSEN/MAGNET），三条线恰好对应本模块的"主线大纲、逐章推进、角色一致性"三个需求。
  • SillyTavern 的角色卡/世界书生态是最成熟的工程化参照物，其数据规范可直接沿用（见调研2）。
  • ATLAS式自动一致性校验（场景间世界状态比对）值得作为生成管线的质检环节。

03角色主线生成方法

核心思路：角色弧光驱动规划，两阶段生成正文。先让AI基于"世界观+世界状态+主脉络+角色档案"规划出该角色的完整弧光与章节大纲，再逐章生成小说文本。

角色弧光（Character Arc）规划

  • 欲望 vs 需求：角色想要什么（表层目标）vs 缺什么（深层缺口）
  • 起点状态 → 终点状态：性格/认知/立场的转变轨迹
  • 谎言→真相：角色相信的错误信念，何时被击碎
  • 主要障碍：来自主脉络中的反派/危机/规则
  • 弧光类型：正向成长、堕落、平稳（工具人）、救赎、幻灭

弧光是"同一世界观，不同角色主线不同"的根本来源——每人有各自的欲望与缺口。

主线差异化的三个机制

  • 视角过滤：每个角色只知道自己视角内的事件（信息差），同一世界事件在各角色线的呈现详略与立场不同
  • 目标驱动路径：角色目标决定他在主脉络大事件中的位置（亲历者/受害者/旁观者/幕后推手）
  • 风格绑定：叙事文风与角色性格挂钩（第一人称内心戏 / 冷静旁观体 / 报信人视角），写在角色卡的 narrating_style 字段

两阶段生成工作流

阶段1：角色弧光+章节大纲
→
用户审阅/修改大纲
→
阶段2：逐章生成正文
→
章末状态回写
→
下一章（携带滚动摘要+下章计划）

每章生成时注入的上下文 = 固定块（世界观规则摘要 + 角色卡 + 关系网）+ 滚动块（前情滚动摘要 + 本章大纲 + 悬而未决的伏笔清单 + 当前世界状态 diff）。固定块保证"人设与规则不崩"，滚动块保证"剧情连续"。

角色主线大纲生成提示词

// 阶段1：一次生成完整角色弧光+章节大纲（JSON输出）
你是资深小说策划。基于以下输入，为角色 {角色名} 规划专属故事主线。

【世界观摘要】{基本盘：风格/年代/背景/核心规则，限500字}
【主脉络关键事件】{调研3编年史中与该角色相关的事件，按时间排列}
【角色档案】{角色卡：基础人设/性格/外貌/说话风格/核心欲望/深层缺口}
【人物关系】{与重要角色的关系及态度}
【世界状态】{开局时的世界状态JSON摘要}

规划要求：
1. 主线必须由角色自身"欲望vs需求"驱动，与主脉络事件交织但不重复大事件原貌
2. 明确角色弧光：起点状态 → 关键转折（至少2次）→ 终点状态
3. 至少一个"与其他可玩角色的交集点"和至少一个"独立分支点"
4. 埋设 3-5 个伏笔（hook），标注计划回收的章节
5. 章节数 {N}，每章大纲含：目标/障碍/转折/情绪基调/涉及NPC/世界事件引用

输出JSON：
{
  "arc": {"start_state":"...","end_state":"...","turning_points":["..."],"type":"growth|fall|flat|redemption"},
  "chapters": [{"no":1,"title":"...","goal":"...","obstacle":"...","turn":"...","mood":"tense|warm|sad|...","npcs":["..."],"world_event_refs":["E-xxx"]}],
  "foreshadows": [{"id":"F-1","content":"...","plant_ch":2,"payoff_ch":8}],
  "intersections": [{"with":"角色B","event_ref":"E-xxx","ch":5}]
}

逐章正文生成提示词

// 阶段2：每章调用一次；滚动摘要与下章计划是RecurrentGPT式递归状态
你是小说写作引擎。撰写 {角色名} 主线的第 {N} 章正文。

【固定上下文】
世界观规则（必须遵守，不得违反）：{规则摘要}
角色卡（性格/口癖/说话风格必须一致）：{角色卡核心字段}
关系与态度：{相关角色关系}
【滚动上下文】
前情摘要（截至第{N-1}章末）：{滚动摘要}
本章大纲：{本章大纲JSON}
未回收伏笔（本章可自然提及）：{foreshadows列表}
当前世界状态变化：{本角色线最近diff}

写作约束：
1. 字数 {1800-2200} 字，第三人称限制视角（只能写{角色名}能感知的内容）
2. 章末必须产出：本章小结(200字) + 下章计划(100字) + 状态变化JSON
3. 若大纲标注世界事件引用，按本角色视角改写，不得披露视角外信息
4. 对话须符合各角色口癖；违反世界观规则的情节一律禁止

输出JSON：
{
  "text": "本章正文...",
  "summary": "本章小结",      // 滚动进入下一章
  "next_plan": "下章计划",      // 滚动进入下一章
  "state_diff": {"hp":-10,"关系":{"角色B":-1},"新物品":["..."]},
  "foreshadow_updates": [{"id":"F-1","action":"planted|advanced|paid_off"}],
  "new_npcs": [{"name":"...","role":"...","card":{...}}]   // 本章新生成NPC自动登记
}

一致性维护清单（长篇不漂移的四道保险）

  • 固定块注入：角色卡/世界观规则每次全文注入（放系统提示词），不依赖模型"记得"。
  • 滚动摘要+下章计划：RecurrentGPT式递归状态，控制上下文长度且保剧情连续。
  • 伏笔台账：伏笔是显式数据（plant/advance/pay_off状态机），章末强制更新，避免烂尾。
  • 章末一致性自检：定期跑"角色口吻校验+规则违反扫描"（可用ATLAS式场景比对），不合格重生成。

04交集与平行宇宙机制

多角色线并存时的核心数据结构是共享事件池 + 世界线管理：世界事件只有一份（来自调研3的编年史），各角色线以自己的视角引用；用户的关键选择产生分歧点，分歧点之后开新世界线。

机制一：共享事件池（交集）

世界事件池（唯一事实源）
→
角色线A：视角内引用改写
＋
角色线B：另一视角引用改写
→
信息差/立场差 = 叙事张力
  • 事件只有一份：E-207"城南大火"发生时间、伤亡、官方说法由事件池唯一确定，任何角色线不得改写事实本体。
  • 视角决定呈现：线A（消防员）写亲历与救人，线B（记者）写调查与隐瞒——读者换角色重读同一事件，获得拼图感。
  • 交集场景：两线在同一事件相遇时，对话与动作以事件池记录为锚，双方角色卡为约束，避免"各说各话"。
  • 参考原型：《冰与火之歌》多POV线交织（同一战争不同章节不同视角）；《428被封锁的涉谷》多主角交叉触发解锁。

机制二：世界线与分歧点（平行宇宙）

世界线编号（参考 Steins;Gate）

  • 基准线 WL-0：未受用户关键选择影响的"原史"
  • 分歧点（Divergence Point）：用户做了不可逆重大选择后开新线
  • 世界线编号 WL-0.1 / WL-0.2…：记录祖先链 parent_worldline + 分歧点事件 + 分歧选择
  • 世界线收束（Convergence）：某些关键节点无论怎么选都会殊途同归——用于控制生成成本，非关键分支自动汇合

蝴蝶效应传播

  • 选择 → 状态 diff → 波及评估（个人级/关系级/区域级/世界级）
  • 个人级：只影响本线后续章节（默认）
  • 关系级：更新关系网，影响交集场景态度
  • 世界级：写回世界状态，事件池新增衍生事件——其他角色线推进到对应时间点时"感知"到变化
  • 传播深度可配置（轻度/中度/深度），默认轻度以控制生成量

分岔与汇合的数据结构

// 世界线管理：分岔记录 + 汇合点 + 视角引用
{
  "worldlines": {
    "WL-0": { "parent": null, "divergence_at": null,
      "state": {...},              // 本线世界状态快照
      "active": true },
    "WL-0.1": { "parent": "WL-0",
      "divergence_at": { "ch": 5, "event": "E-207",
        "choice": "救出老师而非学生" },   // 用户的关键选择
      "converge_back": "WL-0@ch12" }   // 世界线收束点（可选）
  },
  "event_pool": {
    "E-207": { "time": "第3章", "facts": "城南大火，死7人，官方称电路老化",
      "truth": "...",                       // 隐藏真相（部分角色线可逐步揭示）
      "referenced_by": ["route-A@ch3", "route-B@ch6"],
      "derived_in": { "WL-0.1": "E-207a 死亡名单变化" } }
  },
  "butterfly": {
    "scope": "regional",                   // personal|relational|regional|world
    "propagated_to": ["route-B"],           // 感知到变化的其他线

}

交集事件处理提示词

【共享事件】{E-xxx 事实描述 + 隐藏真相 + 各方立场}
【本线角色】{角色卡摘要}　【对线角色】{对方角色卡摘要}
【关系现状】{关系网中的当前态度}

撰写两线在本事件中的交集场景。要求：
1. 事件事实（时间/地点/伤亡/官方说法）必须与事件池完全一致，不得改写
2. 双方言行必须符合各自角色卡与关系现状
3. 制造信息差：本线角色知道而对方不知道的信息、反之亦然，各至少1条
4. 结尾输出交集结果JSON：双方关系变化 / 新增信息差 / 是否产生分歧条件
{本线视角版本：以{角色名}的限制视角叙述，300字}
{对方视角版本：以{对方名}的限制视角叙述，300字}

成本控制要点（平行宇宙最容易失控的地方）

  • 默认收束：绝大多数选择走"个人级"影响，不新开世界线；只有调研5定义的"关键选择"（世界级分歧）才开线。
  • 懒生成：新世界线不预生成全部章节，用户切换/推进到时才生成；基准线事件池可复用。
  • 世界线上限：建议单存档同时活跃 ≤3 条世界线，旧线归档为"史书"供回看。
  • 波及评估用代码不用LLM：选择的 scope 由选择节点定义（见调研5），确定性判断，避免LLM自由发挥导致爆炸式传播。

05NPC 动态生成

NPC 分两层管理：重要NPC（预生成完整角色卡，进入关系网）与随机NPC（按需懒生成、简化卡、可转正）。

维度重要NPC随机NPC
生成时机开线前预生成（或来自调研2的批量生成）剧情需要时即时生成（懒加载）
角色卡完整字段（人设/性格/外貌/口癖/目标/秘密）简化卡：姓名/身份/一句话人设/口癖标签
状态管理进入关系网与状态追踪，全程一致局部缓存；出现≥2次自动转正
一致性固定块注入每章缓存注入所在章节；转正后升为固定块
与世界观深度绑定主脉络需通过"世界观适配校验"（时代/地域/规则不冲突）

随机NPC生成提示词

// 章节生成时发现需要新NPC（如"酒馆老板"），即时生成并登记
【需求】本章需要一个NPC：{剧情功能：情报来源/氛围路人/小冲突对手/受害者}
【世界观约束】{时代/地域/社会阶层/规则怪谈相关禁忌}
【现有NPC名单】{姓名列表——避免重名与职能重复}

生成一个随机NPC，输出JSON：
{
  "name": "符合时代地域的姓名",
  "role": "身份职业",
  "one_liner": "一句话人设（含一个记忆点）",
  "speech_tag": "口癖或说话风格标签",
  "hook": "可发展的伏笔钩子（可选）",
  "promotion_hint": "若用户深交，可发展为?"   // 转正预案
}
约束：不得与现有NPC重名、职能重复；不得违反世界观（如规则怪谈中NPC必须遵守场所规则）。

转正机制（路人→重要角色）

  • 触发条件：出现≥2章 / 用户选择深交 / 剧情需要其承担功能
  • 转正流程：简化卡 → 补全完整角色卡（目标/秘密/关系网挂载）→ 固定块注入
  • 回溯一致：转正时生成"过往经历补丁"，与已出场章节不矛盾

NPC 池管理

  • 按场景类型缓存：酒馆/衙门/市集各有常用NPC池，同一场景复用提高真实感
  • 姓名生成约束：时代感命名表（古风/现代/西幻），避免出戏
  • 职能去重：已有"情报贩子"则不再生成同类

07三方案对比与推荐路线

维度方案A 单LLM两阶段方案B 角色Agent化方案C 混合编排
实现复杂度低高中
成本低高（多Agent多轮）中
角色一致性中（靠注入+校验）高（Agent专责扮演）高
交集/分岔可控性高（确定性代码管世界线）中高
叙事质量高高（对话更活）高
长篇稳定性中中高（递归状态+校验）
适合阶段MVP高拟真角色扮演产品生产环境

第一阶段 MVP（1-2周）：方案A

单LLM两阶段：角色弧光+章节大纲一次生成 → 逐章正文（滚动摘要递归）。固定块+滚动块注入，伏笔台账，章末状态回写。先跑通"选角色→读到自己专属主线"的完整体验。

第二阶段 增强（2-3周）：加入共享事件池与世界线

实现事件池引用改写（交集）+ 分歧点开线（平行宇宙）+ 波及评估 + 懒生成与收束。此阶段后，"换角色重读同一事件"与"关键选择开新宇宙"两个核心卖点成立。

第三阶段 扩展（2-3周）：NPC动态生成与一致性校验

NPC池+转正机制；引入 ATLAS 式场景一致性自动校验与角色口吻自检，重生成不合格章节。参考 IBSEN 的导演-演员分层：大纲Agent管剧情，角色扮演Agent管对话质量。

第四阶段 产品化

前端角色选择界面 + 世界线切换视图（分岔树可视化，参考 Steins;Gate 收束图式）+ 多线并读。TRAE 落地路径：Python 脚本管状态/事件池/世界线（确定性代码）+ LLM API 负责大纲与正文 + Skill 封装"输入角色ID → 输出章节包"。

核心结论

  • 两阶段生成是标配（Re³/DOC/Dramatron 共同结论）：大纲先行+用户可改，正文逐章递归——不要让AI一次性自由发挥长篇。
  • 角色差异化的根在弧光：欲望vs需求+视角过滤+风格绑定，三件套保证"同世界观、不同人生"。
  • 事件池唯一、世界线显式：交集靠共享事实源+视角改写；平行宇宙靠显式世界线数据+懒生成+默认收束，严控成本。
  • 长篇一致性靠工程不靠模型自觉：固定块注入、滚动摘要、伏笔台账、自动校验四道保险。
  • 衔接调研5：本模块产出的章节正文与 choice_history，正是剧情节点控制工具的操作对象。
