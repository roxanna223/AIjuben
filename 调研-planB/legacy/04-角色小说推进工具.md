# 调研 04：角色小说模拟推进工具

> 目标：用户选定一个角色后，生成该角色专属的故事主线（不同角色可产生交集/平行线，含重要角色与随机 NPC）；结合世界观、剧情、人物关系、目标与世界主脉络，把小说正文真正生成出来。

---

## 一、结论先行

1. **「选定角色 → 生成 TA 视角的专属主线」已是被商业产品验证的形态**——MidReal 的角色扮演模式（代入任意角色、按角色视角续写）和彩云小梦的角色互动/平行世界回溯就是直接竞品参照。
2. 技术上有两条成熟路线，且**应当组合使用**：
   - **分支引擎路线**（ink / ChoiceScript / Twine）：确定性强、可控、可测试，适合"骨架"；
   - **LLM 生成路线**（MidReal 式自由生成 + 记忆系统）：内容无限、NPC 可随机涌现，适合"血肉"。
3. **角色交集与平行宇宙的正确实现 = 单一共享世界状态 + 多视角渲染**，而不是每条角色线各跑一个独立故事。这一点几乎所有参考架构都指向同一结论。

## 二、竞品与工具盘点

### 2.1 直接对标的商业产品

| 产品 | 与本需求相关的机制 | 可借鉴点 |
|---|---|---|
| **MidReal**（midreal.ai，MIT/NYU/剑桥/普林斯顿团队） | 一句话生成长篇；**记忆跨度引擎**（号称百万字级不崩人设、伏笔一致）；**关键节点提供分支选项也可自写指令**；**角色扮演模式：代入任意角色，AI 按该角色视角续写**；自动配图；EPUB/PDF/剧本导出 | 「角色视角续写 + 节点分支 + 超长记忆」三件套就是本需求的完整产品形态；可作为体验基准 |
| **彩云小梦** | 世界设定（3000 字背景 + 角色词条含关系/生死状态）驱动续写；一次生成 3 条不同走向供选择；**平行世界回溯：回退到任意节点改剧情，改动节点打蝴蝶标记，后续剧情跟着变**；角色有记忆（越聊越熟）；可切换自研/DeepSeek/豆包模型 | **「平行世界回溯 + 蝴蝶效应标记」是角色平行线的现成 UX 范式**；词条式人物定义与调研 02 的角色卡思路一致 |
| **AI Dungeon** | 第二人称角色代入、Lorebook 保证设定一致、分支存档 | 自由度上限参照；但无主线结构，容易发散——证明"纯自由生成"需要主线骨架约束 |
| **CoNexus** | 无代码分支故事 + AI 生成内容/配图/配音，可调节奏与风格，可重玩 | 分支故事在线化的产品形态参考 |

### 2.2 叙事引擎（骨架层候选）

| 引擎 | 特点 | 适用性 |
|---|---|---|
| **ink**（inkle 出品，80 Days / Heaven's Vault 同款） | 叙事脚本语言，分支/变量/条件逻辑，可嵌 Unity，也有 JS 运行时 | **首推**：工业级分支叙事标准，LLM 可以生成 ink 代码作为故事骨架 |
| **ChoiceScript**（Choice of Games） | 文本游戏脚本，强在数值/属性条件分支（stats-driven） | 「大选择影响属性、属性门槛解锁分支」机制的参考 |
| **Twine** | 可视化段落链接，免费开源，支持变量与 JS | 快速原型与分支结构可视化 |
| **Ren'Py** | 视觉小说引擎（Python），多媒体成熟 | 若后期做视觉小说形态可选 |
| **Narra**（见调研 03） | YAML 声明剧情线 + 世界规则 + Go 内核仿真 | 若采纳 Narra 体系，剧情线可直接在其框架内声明 |

### 2.3 角色驱动生成（血肉层候选）

- **SillyTavern 群聊模式**：多角色同场自主对话，是"重要角色交集"场景的现成技术参照（多 Agent 群聊 + 世界书）。
- **Inworld AI**：带性格、记忆、情绪的 NPC 引擎，给设定即产对话树与动机逻辑——随机 NPC 生成参照。
- **Mythos**（开源）：雪花法从概念→人物→场景→章节的结构化生成管线，多档模型路由控成本。
- **NovelAI Lorebook / Memory**：长篇一致性的记忆机制标杆。

## 三、关键机制设计（本项目怎么实现）

### 3.1 总体架构：共享世界 + 视角渲染
```
世界主脉络（调研03产出：大事年表 + 世界状态）
        │
        ▼
角色主线规划器：选定角色 → 从世界年表中截取与TA相关的事件带，
        结合其动机/目标生成"个人主线大纲"（三幕/章节结构）
        │
        ▼
章节生成器（LLM）：按大纲逐章生成正文
  · 注入：世界观Lorebook + 角色卡 + 关系网 + 世界当前状态
  · 该角色不在场的事件 → 不进正文，只影响世界状态（后台演化）
        │
        ▼
交集检测：当两角色主线的时间地点相交 → 生成"交集场景"，
        同一事件在两个角色线中各有一份视角版本
```

### 3.2 角色交集 / 平行宇宙
- **交集**：世界状态是唯一事实源。角色 A 与 B 在某章相遇 → 该事件写入世界状态；B 线的同一事件从 B 视角重写。两条线共享因果，不产生矛盾。
- **平行宇宙**：用户在大选择点（见调研 05）产生分支 → 复制世界状态快照，形成分支线。彩云小梦的「回溯节点 + 蝴蝶标记」即此机制的 UX 范本：**分支不是重写历史，而是从快照分叉**。
- 技术要点：世界状态必须可快照、可 diff（JSON + seed 化随机，同调研 03 结论）。

### 3.3 重要角色与随机 NPC
- **重要角色**：来自调研 02 的角色卡，全字段注入，语气用 `mes_example` 锚定。
- **随机 NPC**：模板化生成（Perchance 式随机表 + Inworld 式"一句话设定→动机逻辑"），用后即写回世界状态成为"次级角色"——下次同地点再出现时可复用，避免"路人甲每次换脸"。
- NPC 行为遵循世界规则（规则怪谈场景下 NPC 也有自己的"已知规则列表"，见调研 03）。

### 3.4 长篇一致性（最大的工程难点）
分层记忆方案（综合 MidReal/NovelAI/Smallville 经验）：
1. **Lorebook 关键词注入**：世界与角色设定按需命中；
2. **章节摘要链**：每章生成 100 字摘要，后续章节携带最近 N 章摘要 + 相关旧章摘要（向量检索）；
3. **伏笔登记表**：显式记录"埋下的伏笔/承诺"，生成新章前检查回收进度——这是网文级长篇不崩的关键，纯靠 LLM 上下文做不到；
4. **角色状态跟踪**：伤势、持有物、关系变化、知识状态（知道哪条规则）作为结构化字段维护，不依赖散文记忆。

### 3.5 骨架 vs 生成的分工（务实建议）
- **主线骨架用 ink/结构化大纲**：幕、章、必经节点、大选择点——确定性、可测试、可人工改；
- **章节正文与 NPC 对话用 LLM 生成**——在骨架约束内发挥；
- 纯自由生成（AI Dungeon 模式）只用于"自由探索"环节，不承担主线。

## 四、推荐落地方案

**MVP：**
1. 输入：世界观 JSON（调研 01）+ 角色卡集（调研 02）+ 世界年表（调研 03）。
2. 主线规划器：LLM 生成所选角色的章节大纲（10-15 章，标注大选择点位置——接口留给调研 05）。
3. 章节生成器：逐章生成，带摘要链 + 伏笔表 + 角色状态表。
4. 分支：大选择点处世界状态快照分叉，UI 上呈现"蝴蝶标记"式时间线。

**验证基准**：同一世界观生成两个角色主线，检查交集事件在两线中的因果一致性——这是该模块的核心验收标准。

**主要风险：**
- 长上下文成本 → 摘要链 + 多档模型路由（Mythos 模式）；
- 角色 OOC（性格漂移）→ 角色卡 `mes_example` + 每章性格自检；
- 多线交织后矛盾 → 世界状态唯一事实源 + 交集事件单次生成多视角渲染。
