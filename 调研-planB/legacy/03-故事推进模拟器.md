# 调研 03：故事推进模拟器（大世界观脉络）

> 目标：不局限于单个角色，建立世界主线的运转脉络。需要一套**运算规则**（完全符合世界观规则，如规则怪谈），能推演世界从某时点开始、未来 N 年如何发展，以"大画面"形式推进。

---

## 一、结论先行

这一环是五个方向里**学术与开源积累最深、但也最需要取舍**的一环。核心结论：

1. **「世界脉络推演」已被验证可行的架构 = 生成式智能体（Generative Agents）+ 游戏规则主持人（Game Master）引擎**。代表作：Stanford/Google 的 Smallville（2023）、a16z 的开源 AI Town、DeepMind 的 Concordia 框架。
2. **「规则怪谈」类世界观有成熟的规则引擎设计模式**（触发条件→生效条件→执行动作 + 玩家知识状态），且有中文开源实现可直接参考。
3. 纯 LLM 模拟在 **50 个智能体以内、数天到数月的模拟时长**内表现可靠；要做"数年大画面推演"，必须用**分层架构**：微观（智能体模拟）只用于关键片段，宏观（年代推演）用规则引擎 + 摘要式 LLM 生成。
4. 完全照搬 Smallville 做"百年世界演化"在成本和一致性上不可行——**混合式（规则引擎驱动大事件 + LLM 填充叙事）是唯一务实路线**。

## 二、三大参照系

### 2.1 Generative Agents / Smallville（斯坦福 & Google, 2023）
- 25 个由 LLM 驱动的智能体生活在小镇里，自主起床、工作、社交；涌现出"自发组织情人节派对"（邀请靠口耳相传从 1 人扩散到 12 人）等未编程行为。
- **核心架构（直接可借鉴）**：
  - **记忆流（Memory Stream）**：带时间戳的全部观察记录；
  - **检索**：按「新近度 × 重要性 × 相关性」打分取出相关记忆注入 prompt；
  - **反思（Reflection）**：定期把原始记忆总结成高层认知（"某人对研究充满热情"）再存回记忆流；
  - **规划（Planning）**：生成日程并递归分解，驱动长期一致行为。
- 论文地址：Generative Agents: Interactive Simulacra of Human Behavior（Joon Sung Park 等）。

### 2.2 AI Town（a16z-infra 开源，MIT 协议）
- Smallville 的 JavaScript/TypeScript 重实现，一键部署（Convex + 任意 OpenAI 兼容 LLM + PixiJS 渲染）。
- 引擎以 **1 现实秒 = 1-5 模拟分钟** 的 tick 循环推进世界；人物由 JSON prompt 定义；记忆存向量库。
- 对本项目的意义：**代码级参考**。怎么设计 tick 循环、怎么调度智能体、怎么做记忆检索，全部开源可读。GitHub: a16z-infra/ai-town。

### 2.3 DeepMind Concordia（google-deepmind/concordia 开源）
- 生成式智能体社会模拟框架，关键设计是 **Game Master（GM）引擎**：GM 负责裁决"每个行动在这个世界里会发生什么"、维护世界状态、推进时间——**这正是"故事推进模拟器"的本体**。
- 智能体只负责"我想做什么"；**世界因果完全由 GM 按世界观规则裁决**。这一职责分离对本项目至关重要：规则怪谈的规则判定就该放在 GM 层，而不是寄希望于各角色自觉。

### 2.4 2025-2026 研究界共识（规模化边界）
- 智能体模拟中，**分工、信息扩散（接近经典 SIR 传播模型）、无协议协作、偶发欺骗**均为可复现的涌现行为。
- **瓶颈在记忆**：10 个智能体稳定；50 个开始记忆漂移、连贯性下降；200 个不做分层记忆/分片就崩溃。2026 年的标准解法 = **分层记忆（个体长期记忆 + 共享世界摘要）+ 分片计算**。
- 大规模参照：Altera 的 Project Sid（Minecraft 中 1000 智能体自组织出经济与政府）证明"文明级"模拟可行，但成本极高。

## 三、规则怪谈类世界观的规则引擎设计

中文社区已有较成熟的拆解（Unity 后室规则怪谈实现、多个开源项目），核心模式：

### 3.1 规则的三段式结构
每条规则 = **触发条件（Trigger）+ 生效条件（Validation）+ 执行动作（Action）**
- 例：「当玩家直视实体 A 超过 3 秒（触发），且玩家未持有绝缘手套（生效），则实体 A 瞬移至玩家身后（动作）」。
- 规则分保护性（必须做）与危害性（不能做）两类；规则本身**既是玩法机制又是叙事元素**——规则怪谈的世界观即规则集。

### 3.2 玩家知识状态（Player Knowledge State）
规则怪谈区别于传统游戏的关键：系统要跟踪"玩家知道了什么"——未知 / 部分知晓（可能片面甚至错误）/ 完全知晓。这条同样适用于 NPC 智能体：**每个智能体有自己的已知规则列表，信息靠事件在世界中扩散**（与 Smallville 的信息扩散涌现行为天然契合）。

### 3.3 可参考的开源实现
- **Narra**（GitHub: gqy20/narra，MIT）：**数据驱动的叙事模拟框架**——Go 权威规则内核 + Godot 客户端；内容包用 YAML 声明场景、人物、地点、事实、物品、行动、剧情线、**世界规则**、AI 对话策略；自带 `simulate --runs 200 --seed 1` 的内容包批量仿真验证工具。**与本项目的需求形态最接近，强烈建议细读**（且与你 Godot 技术栈吻合）。
- **Unity_RuleNonsense**（GitHub: Vae078）：观察者模式的全局状态管理器（订阅/发布状态变化），适合小规模规则怪谈原型。
- 通用模式：规则库存字典（ID→规则），状态机跟踪世界状态，行动系统定义可选动作。

## 四、"大画面 N 年推演"的架构设计（本项目方案）

### 4.1 分层模拟架构（推荐）
```
┌─ 宏观层：编年史引擎（规则引擎 + LLM 摘要）
│   输入：世界观规则集、当前世界状态、时间跨度（如 50 年）
│   机制：以"年/时代"为 tick，规则引擎判定结构性变化
│        （势力消长、资源、规则变异），LLM 把状态变化
│        写成编年史条目 → 产出世界大事年表
├─ 中观层：阶段快照
│   从年表中选取"关键转折点"，生成该时期的世界快照
│   （势力版图、存活人物、新规则、社会氛围）
└─ 微观层：智能体模拟（按需）
    只对用户选定的时期/地点跑 Smallville 式模拟，
    为"角色小说推进"（调研 04）提供具体事件素材
```

### 4.2 世界状态的数据化
- 世界状态 = 结构化 JSON（势力、资源、规则清单、关键人物存活表、时间），**规则引擎直接操作状态**（确定性、可复现、可 seed），LLM 只负责状态↔叙事的互译。Narra 的"Go 权威规则内核 + YAML 内容声明"就是这个思路。
- **可复现性**：所有随机走 seed；每次推演产出可 diff 的年表，方便多次推演取优。

### 4.3 规则一致性保障
- 世界规则（调研 01 产出的"核心规则"字段）编译为规则引擎的判定逻辑 + 注入 LLM 的 system 约束，双保险；
- 每条编年史条目生成后过一遍**规则自检器**（LLM 校验该事件是否违反任何编号规则）；
- 信息扩散用显式模型（谁知道什么规则/事件，按社交网络传播），不要依赖 LLM 隐式推理。

### 4.4 成本与规模控制
- 微观模拟控制在 **≤50 个活跃智能体**，超出用群体抽象（"市民阶层整体反应"）；
- 宏观层每个 tick 1-2 次大模型调用即可，50 年推演 ≈ 50-100 次调用，成本可控；
- 记忆用"共享世界摘要 + 个体长期记忆"分层（2026 研究界标准解法）。

## 五、推荐落地方案

1. **先读两个仓库**：`a16z-infra/ai-town`（智能体 + tick 循环 + 记忆流）和 `gqy20/narra`（规则内核 + YAML 世界规则 + 批量仿真）——前者给微观模拟，后者给宏观架构，且 Narra 用 Godot 客户端，与你现有 Godot 经验衔接。
2. **MVP 只做宏观层**：世界状态 JSON + 规则引擎（YAML 声明规则）+ LLM 编年史生成器，输入世界观基本盘 → 输出 N 年大事年表。这是"大画面推进"的最小可行形态。
3. 微观层后置：等调研 04（角色小说）确定需要哪些事件素材，再决定智能体模拟的粒度。
4. 规则怪谈项目额外做：**玩家/角色知识状态表**（谁知道哪条规则、何时得知、信息是否正确）——这是怪谈类张力的发动机。

**主要风险：**
- 长时间跨度下 LLM 叙事漂移 → 靠"状态由规则引擎权威维护，LLM 只翻译"缓解；
- 规则集增大后判定冲突 → 规则需带优先级/作用域字段，内容包级仿真（Narra 的 simulate 模式）提前暴露。
