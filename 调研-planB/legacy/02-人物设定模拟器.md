# 调研 02：人物设定模拟器 / 编辑器

> 目标：基于已生成的世界观，自动生成主要人物及字段（基础人设、性格、外貌描写等），并可编辑。

---

## 一、结论先行

**「角色卡（Character Card）」已经是一个有着开放社区规范（V2/V3）、上万张共享卡片、多个开源编辑器的成熟生态**——这是本项目五个方向中「现成标准最多、最不需要从零造轮子」的一环。推荐直接采用 **chara_card_v2/v3 规范作为人物数据结构**，在其上做「世界观驱动的人物生成管线」。

---

## 二、核心资产：Character Card 规范（V2 → V3）

由 SillyTavern（酒馆）生态发展出的角色卡开放规范，可直接作为人物设定的固定字段格式：

### V2 规范字段（当前社区 90%+ 使用，事实标准）
| 字段 | 作用 |
|---|---|
| `name` / `nickname` | 角色名 / 称呼 |
| `description` | 核心设定（外貌、身份、背景，AI 必读） |
| `personality` | 性格特征摘要 |
| `scenario` | 场景设定 |
| `first_mes` | 开场白 |
| `mes_example` | 示例对话（让 AI 学习说话风格，对"角色小说推进"环节极重要） |
| `system_prompt` | 角色底层行为指令 |
| `post_history_instructions` | 历史后指令（高权重动态行为约束） |
| `alternate_greetings` | 备选开场（支持多分支开局） |
| `tags` / `creator` / `character_version` | 元信息 |
| `character_book`（内嵌 Lorebook） | 该角色专属的世界书条目 |

### V3 新增（2025 年起，SillyTavern 1.17+ 支持）
- **assets 素材系统**：一张卡携带头像、背景图、表情差分（happy/sad/angry…）、甚至语音/Live2D——**正好对接"大选择需要配图"的多媒体需求**
- **.charx 格式**：ZIP 打包（card.json + assets/ 目录），不再受 PNG 单图限制
- 角色书强制支持 `use_regex` 和 `constant`（常驻条目），跨前端行为可预测
- `source`、`creation_date` 等防篡改元信息

**存储巧思**：V2 把 JSON 塞进 PNG 的 tEXt chunk——图即卡，分享即导入。

### 可直接用的编辑器/构建器
- **Chara Snap**（charasnap.com）：免费在线角色卡编辑器，支持 V2/V3，可导出 .charx
- **ST Card Builder**（st-card-builder.vercel.app）：在线可视化 V3 卡片构建
- **SillyTavern 本体**：开源（GitHub 200+ 贡献者），自带角色卡编辑 + 世界书 + 群聊模式
- 卡片分享平台：CHUB（chub.ai，15000+ 卡）、ClawHub（中文）

## 四、关键机制：怎么"根据世界观自动生成人物"

社区与工具验证过的做法：

1. **世界观上下文注入**：把调研 01 产出的世界观基本盘（风格/年代/核心规则/势力）作为 system context，要求 LLM 生成「属于这个世界」的人物——Talefy 强调的"人物设计必须匹配世界观（服装、配饰、社会位置）"。
2. **关系网驱动生成**（Dunia 模板原则）：不孤立生成人物，而是先生成「关系网骨架」——主角需要：一个盟友、一个对手、一个欠他人情的人、一个掌握秘密的人……每个节点扩写成完整人物。互动小说的人物价值 = 他在分支中的作用。
3. **字段分层**（借鉴 Story321 + Talefy + 角色卡规范，建议的人物 schema）：
   - **基础人设**：姓名、年龄、身份/职业、社会位置
   - **外貌描写**： prose 描写 + AI 绘图提示词（双份，一份给文本引擎一份给图像引擎）
   - **性格**：核心特质 3-5 个 + 性格缺陷（flaw）+ 盲点
   - **动机层**：想要的东西（want）、需要的东西（need）、秘密、恐惧
   - **反应倾向**（互动小说关键）：压力下的反应模式（战/逃/骗/求）、会说谎的条件、会翻脸的底线
   - **声音样本**：示例对话 2-3 段（对应角色卡 `mes_example`，保证后续生成时语气一致）
   - **关系**：与其他人物的关系及关系背后的"情感债务"（亏欠/愧疚/爱慕/怨恨）
4. **自动补齐 + 人工确认**：与世界观向导同一套交互——AI 补全字段标 `auto_generated`，用户在编辑器里逐条采纳。
5. **性格验证环节**：生成后用「面试式对话」自动 QA——让 LLM 扮演该角色回答 5 个压力问题，检查回答是否符合 personality 字段（Character.AI 模式的产品化）。
6. **一致性锚定**：人物卡内嵌 `character_book`（角色专属 Lorebook），保证长篇生成时该角色的事实不漂移。

## 五、推荐落地方案

**MVP：**
1. 人物数据结构直接采用 chara_card_v3 JSON Schema（GitHub: kwaroran/character-card-spec-v3；完整字段定义见 nossebro 的 Gist）。
2. 生成管线：世界观 JSON → LLM 生成「人物关系网骨架」→ 逐节点扩写成完整角色卡 → 性格验证 QA → 输出 .charx / JSON。
3. 编辑器：前期可直接用 Chara Snap / SillyTavern 做人工微调，验证数据结构；后期再自建内嵌编辑器。

**与世界观环节的衔接**：人物卡的 `scenario` 字段引用世界观版本号；人物 Lorebook 与世界观 Lorebook 合并注入后续生成环节。

**风险：**
- 人物容易"模板脸"（AI 偏爱安全人设）→ 在生成 prompt 中强制要求缺陷、秘密、矛盾点；
- 人物与世界观规则冲突 → 生成后跑一遍规则自检（同世界观环节的一致性校验器复用）。
