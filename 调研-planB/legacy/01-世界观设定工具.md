# 调研 01：世界观设定工具

> 目标：自然语言描述 → AI 辅助生成完整世界观；支持自动补齐、多轮沟通完善；最终输出**固定格式的基本盘字段**，字段填满即代表世界观可进入下一步剧情开发。

---

## 一、需求拆解

| 子需求 | 关键点 |
|---|---|
| 自然语言生成世界观 | 用户一句话/一段话 → 结构化世界观初稿 |
| 自动补齐 | 用户没说的部分（历法、势力、经济、规则）AI 主动补全并标注「待确认」 |
| 多轮完善 | 像对话一样反复修改，AI 记住已定稿内容、不跑偏 |
| 固定格式基本盘 | 风格、年代、故事背景、开场设定等字段 schema 化，全部填完 = 世界观冻结 |
| 一致性校验 | 修改 A 字段时不破坏 B 字段（规则、时间线不冲突） |

结论先行：**现成工具没有一个是"开箱即用"的，但「结构化 Schema + LLM 多轮对话 + Lorebook 式持久记忆」的自建管线完全可行，且是 2025-2026 年的主流做法**。推荐路线见第五节。

|---|---|---|---|---|

| 工具 | 特点 | 对本项目的价值 |
|---|---|---|

| **Ludo.ai / Inworld AI** | 游戏向：Ludo 生成 lore/任务结构；Inworld 生成带性格记忆的 NPC | 游戏化方向的补充参考 |

### 2.3 中文生态

- 国内互动小说/AI 写作产品（彩云小梦、MidReal 等）多偏「一键生成故事」而非「世界观 schema 管理」，可作为竞品体验参考，不建议依赖。
- FictionLab 的《Custom Scenario Instructions》文档把世界观指令拆成 **World & Setting / Narrative & Style / Atmosphere & Lore / Character Dialogue & Behavior** 四层，是一套很实用的提示词组织范式。

## 三、关键机制调研结论

### 3.1 「基本盘字段」应该怎么设计

综合 World Anvil 模板、Dunia 的互动故事世界观模板、Mythos 的资产 schema，面向**互动小说**的基本盘字段建议（比传统小说模板更强调「可玩的压力点」）：

**第一层：冻结必填项（填完才可进入剧情阶段）**
1. 风格基调（tone）：如黑暗悬疑 / 轻松日常 / 规则怪谈
2. 年代与时空：时代、地点、历法
3. 世界核心规则（inviolable rules）：魔法代价、死亡规则、怪谈规则——**规则怪谈类项目这是第一字段**
4. 故事背景：当前世界处于什么张力之中（什么社会规范制造了最大冲突）
5. 开场设定：主角处境、激励事件（inciting incident）
6. 叙事约束：视角（第一/第三人称）、时态、文风参考

**第二层：自动生成+用户确认项**
7. 势力/组织及其相互关系（外交网）
8. 地理与关键地点
9. 历史大事件时间线
10. 经济/资源逻辑（稀缺性驱动选择）
11. 禁忌与代价（违反规则会发生什么）

**第三层：互动小说特有的字段（传统模板没有、必须有）**
12. **分支钩子（branching hooks）**：什么玩家行为会强制改变局势（例：拒绝付款 → 线人敌对）
13. 待解谜团清单（留白管理：哪些是故意不说的）

> Dunia 的模板原则值得采纳：**每个字段必须能制造"可玩的压力"**，纯装饰性设定（玩家永远不会遇到的语言学细节、贸易路线）不进核心层。

### 3.2 「自动补齐 + 多轮完善」怎么实现

业界已验证的机制，按推荐度排序：

1. **Schema 驱动对话**：把基本盘定义成 JSON Schema。每轮对话后让 LLM 输出「当前 schema 填充状态 + 空缺字段的补全提案 + 对用户刚修改内容的冲突检查」。Mythos 项目已验证「JSON 结构化输出 + schema 校验」可靠。
2. **Lorebook / World Info 持久记忆**（NovelAI、SillyTavern）：每条设定 = `{关键词组, 条目内容, 注入优先级}`。生成时按关键词命中动态注入上下文，解决 LLM 上下文长度限制和"失忆"。**这是多轮完善不跑偏的核心机制**。
3. **矛盾检测**：Storyflow 的卖点即「AI 读完整块画布后指出设定矛盾」。自建时等价做法：每轮把变更字段 diff 连同相关条目发给 LLM 做一致性审查。
4. **待确认标记**：AI 自动补齐的字段统一打 `auto_generated: true`，用户在编辑器里逐条「采纳/修改/删除」，采纳后转为冻结——这正是「字段填完即完整」的交互闭环。
5. **多档模型路由**（Mythos）：字段补全/摘要用便宜快模型，核心规则推演用大模型，控制成本。

### 3.3 提示词工程要点

- FictionLab 分层指令范式：World & Setting（时空结构）→ Atmosphere & Lore（氛围与神话层）→ Narrative & Style（视角/时态/文风）→ Character Behavior（角色如何说话行动）。四层分离便于逐层冻结。
- 规则类世界观（规则怪谈）需要把规则写成**编号硬规则 + 违反后果**，并要求 AI 在每次输出前自检「本段是否违反任何编号规则」。
- 多轮完善的 system prompt 关键指令：已定稿字段不可单方面推翻，如必须改动需显式提示用户确认（防"对齐漂移"）。

## 四、竞品差距分析（为什么没有现成品）

| 能力 | World Anvil | NovelAI | AI Dungeon | 自建管线 |
|---|---|---|---|---|
| 固定字段 schema | ✅ 强 | 中（自由条目） | 弱 | ✅ 可定制 |
| 自然语言生成 | 中 | ✅ | ✅ | ✅ |
| 多轮完善 + 记忆 | 弱 | ✅ Lorebook | 中 | ✅ |
| 字段填满 → 流转下一环节 | ❌ | ❌ | ❌ | ✅（这是产品逻辑，只能自建） |
| 可嵌入自己产品 | ❌ SaaS | ❌ | ❌ | ✅ |

**结论：生成与记忆机制全部有成熟参照（Lorebook 机制 + schema 化输出），但「字段驱动的工作流」是产品层逻辑，必须自建；技术上无硬门槛。**

## 五、推荐落地方案（能做到优先）

**MVP 路线（1-2 周可出原型）：**
1. 定义基本盘 JSON Schema（按 3.1 三层字段）。
2. 一个对话式向导：LLM 每轮输出「补全提案 + 冲突检查 + 当前完成度 %」。
3. 持久层直接用 Markdown/JSON 文件（Obsidian 式）或 SillyTavern world_info 格式，保证后续环节（人物、剧情）可程序读取。
4. 引擎：Claude/GPT API；字段补全用小模型，规则推演用大模型。

**进阶：**
- 参考 SillyTavern 开源代码实现 Lorebook 注入器；
- 加「世界观冻结」动作：冻结后生成只读版本 + 版本号，后续所有环节（人物/剧情/节点）锚定该版本。

**主要风险：**
- 长世界观下 LLM 仍可能漏规则 → 靠 Lorebook 关键词注入 + 每轮自检缓解；
- 字段 schema 设计贪多 → 坚持「只收能制造剧情张力的字段」。
